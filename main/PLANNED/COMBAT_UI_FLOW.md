# [예정 항목] 전투 입력 흐름 개편 명세

> 현재 업로드된 wtmg 저장소에는 전투 UI/서버 코드가 없으므로 이 항목은 **코드 적용 전 명세**입니다.

## [핵심 원칙]
상위 메뉴를 누르는 것만으로는 턴을 소비하거나 적의 공격을 발생시키지 않는다.

상태 흐름:
`IDLE → CATEGORY_OPEN → OPTION_SELECTED → TARGET_SELECT(필요 시) → CONFIRM → RESOLVE → IDLE`

## [공격]
1. `공격` 클릭 → 무기/공격 방식 하위 패널만 연다.
2. 단검, 활, 맨손 등 공격 수단 선택 → 아직 공격 처리하지 않는다.
3. 적 대상 선택 → `확정` 버튼 활성화.
4. 확정 시에만 `battle_action(action="attack", target_index=...)` 호출.
5. 확정 전 취소/패널 변경은 적 턴을 발생시키지 않는다.

## [전략]
`전략` 클릭 시 `기술 / 특성 / 방어 / 휴식 / 대화 / 도주` 등 하위 항목 표시.
- 기술/특성: 항목을 선택한 뒤 `targeting` 메타데이터에 따라 대상 선택.
- 자신 대상 또는 전장 전체 효과는 대상 단계 생략 가능.
- 방어처럼 별도 대상이 없는 행동은 확인 창을 거쳐 실행.
- 단순 패널 열기/탭 전환은 서버 액션으로 처리하지 않는다.

## [아이템]
1. `아이템` 클릭 → 사용 가능한 아이템 하위 패널.
2. 아이템 선택 → `target_type`에 따라 적/아군/자신 대상 선택.
3. 대상이 필요한 아이템은 대상 미선택 상태에서 사용 버튼 비활성화.
4. 확정 후에만 아이템 소비, 효과 적용, 적 턴 진행.
5. 회복약을 적에게 사용하거나 공격 아이템을 아군에게 쓰는 등 잘못된 대상은 서버에서도 검증.

## [대상 선택 규칙]
각 기술/특성/아이템에 다음 메타데이터를 둔다.
- `target_type`: `enemy | ally | self | point | all_enemies | all_allies | none`
- `target_count`: 1 이상의 정수
- `range_m`: 사거리
- `requires_line_of_sight`: 시야 필요 여부
- `allow_dead`: 전투불능 대상 허용 여부

클라이언트 검증과 서버 검증을 둘 다 수행해야 한다.

## [서버 API 권장 변경]
현재 `battle_action`은 action/name/target_index만 받아 즉시 해결한다.
다음 둘 중 하나 권장:

A. 기존 API 유지:
- UI에서 확정 전에는 `battle_action`을 절대 호출하지 않는다.
- 확정 시에만 기존 파라미터를 전송.

B. 확장 API:
- `option_id`
- `target_indices`
- `confirm: true`
를 추가하여 잘못된 중간 호출을 서버에서도 거절한다.
